# Komosion Helpdesk Agent — n8n Workflows

Automated helpdesk intake and WIP tracking for Komosion, built on n8n.

---

## Workflows

### Komosion Helpdesk Intake — Phase 1 - Ver2

**File:** `Komosion_Helpdesk_Intake___Phase_1___Ver2.json`

Polls the `support@` Gmail inbox every 2 minutes, triages incoming emails, creates structured tickets, and links them to WIP tasks.

#### What it does

| Stage | Description |
|---|---|
| **Poll** | Gmail trigger polls `truc.pham@komosion.com` inbox on a configurable interval |
| **Triage** | Rules-based pre-filter (allowlist/blocklist domains, senders, header keywords) then LLM classifier (OpenAI) confirms whether the email is a genuine support ticket |
| **Dedup** | Voyage AI embeddings + Supabase vector search detects repeat/similar tickets (cosine similarity threshold 0.85) |
| **Ticket creation** | Structured ticket logged to Supabase `tickets` table and Google Sheet (`tickets` tab); ticket ID prefixed `TKT` |
| **WIP linking** | LLM matches ticket to an existing WIP task or creates a new one in Supabase `wip_tasks`; WIP fields (project/client, task, lead, next step) generated by OpenAI |
| **Sheet sync** | `wip_tasks` Google Sheet tab mirrors Supabase for AppSheet; updated on ticket create, note append, and status change |
| **Note history** | All notes stored in `wip_notes`; a DB trigger (`trg_sync_latest_note`) syncs `latest_note` and `latest_note_at` back to `wip_tasks` |
| **Status updates** | Incoming replies update ticket status and append a note; unified status lifecycle: `new → to_do → in_progress → waiting_client / blocked → complete → closed` |
| **Error handling** | Workflow error trigger logs failures to the `errors` sheet tab |

#### System config

Tunables are set in the **Config** / **Config1** nodes (or overridden via Supabase `system_config`):

| Key | Default | Description |
|---|---|---|
| `pollIntervalMinutes` | 2 | Gmail poll frequency |
| `markAsRead` | true | Mark processed emails as read |
| `helpdeskSheetId` | *(sheet ID)* | Google Sheets document ID |
| `ticketsSheetTab` | `tickets` | Sheet tab for tickets |
| `wipTasksSheetTab` | `wip_tasks` | Sheet tab for WIP tasks |
| `supabaseTicketsTable` | `tickets` | Supabase table for tickets |
| `supabaseEmbeddingsTable` | `ticket_embeddings` | Supabase vector table |
| `dedupThreshold` | 0.85 | Cosine similarity threshold for dedup |
| `dedupTopK` | 5 | Number of similar tickets to retrieve |
| `repeatClusterCap` | 3 | Max cluster size before flagging repeat |
| `ticketIdPrefix` | `TKT` | Prefix for generated ticket IDs |

### Komosion Daily WIP Sync — Phase 3.2 _(in progress / testing)_

**File:** `Komosion_Daily_WIP_Sync___Phase_3_2.json`

Daily standup transcript → structured WIP task updates in Supabase. Replaces the legacy Google Apps Script (`main.js`) with an n8n workflow backed by Supabase instead of Google Sheets.

> **Status:** active development — manual trigger used temporarily; calendar/webhook trigger will be restored in Phase 3.4. Monthly rollover (1st-of-month) is out of scope here and will be a separate Phase 3.3 workflow.

#### What it does

| Stage | Description |
|---|---|
| **A — Trigger** | Manual trigger (temporary for testing); webhook `POST /daily-wip-sync` is the target trigger |
| **B — Transcript fetch** | Looks up today's calendar event matching `daily_meeting_title_pattern` (from `system_config`), picks the latest attached Google Doc transcript, exports to plain text, and cleans it (`cleanTranscriptContent` logic ported from AppScript) |
| **C — LLM classify + extract** | Two-stage LLM call: (1) classify which active projects are mentioned; (2) per-project extract WIP actions (`{action, task, lead, status, note, next_step, existing_task_id}`). Model and tunables read from Supabase `system_config` |
| **D — Persist** | Applies actions to Supabase `wip_tasks` with `continueOnFail`; Match Layer A guards creates (flips create→update if confidence ≥ `wipConfidenceThreshold`); meetings upserted by `calendar_event_id`; `meeting_tasks` junction populated |
| **Cascade close** | Completed WIP tasks trigger `tickets SET status='resolved'` for all linked tickets |
| **Sheet sync** | `wip_tasks` Google Sheet tab updated on create/update/complete (same pattern as Phase 1) |
| **Email summary** | Gmail sends success email with C/U/D counts, auto-closed tickets, errors list, and double-run warning; separate emails for no-meeting, no-transcript, and no-actionable-items cases |
| **Double-run guard** | Checks `meetings` + `meeting_tasks` tables; flags `doubleRunWarning` in summary if today's meeting was already processed |

#### System config keys (from Supabase `system_config`)

| Key | Description |
|---|---|
| `daily_meeting_title_pattern` | Substring to match standup calendar event title |
| `transcript_title_pattern` | Prefix used to identify transcript Drive files |
| `llm_model` | Model ID for the classify + extract LLM calls |
| `wipConfidenceThreshold` | Confidence threshold for Match Layer A create→update flip |

#### Parity with AppScript

See `parity_report_3_2.md` for a full comparison. Key intentional drifts: storage is Supabase not Sheets; `merges` action dropped (was dead code); sort/highlight (UI concern) dropped; monthly rollover deferred to Phase 3.3.

### Komosion Vector Indexer _(parked — not active)_

**File:** `vector_indexer.json`

Webhook-driven pipeline that upserts text embeddings into a Supabase `embeddings` table using Voyage 3 Large (1024 dims). Kept for future use; currently has known issues and is not activated.

#### What it does

| Stage | Description |
|---|---|
| **Receive** | Webhook POST `/vector-index` accepts `source_type`, `source_id` (UUID), `content`, and optional `metadata` |
| **Validate** | Validates required fields and allowed `source_type` enum values |
| **Config load** | Reads `embedding_model`, `embedding_dimension`, `embedding_input_type` from Supabase `system_config` |
| **Upsert** | Deletes existing row keyed on `(source_type, source_id)`, then inserts new embedding via Supabase Vector Store |
| **Error logging** | Failures written to `embedding_errors` table; error response returned with stage info |

#### Additional credential required

- **Voyage AI API** — text embedding generation (`voyage-3-large` model)

## Credentials required

Configure these credential types in your n8n instance (no secrets stored in this repo):

- **Gmail OAuth2** — inbox polling and sending replies
- **Google Sheets OAuth2** — logging to helpdesk spreadsheet
- **Supabase API** — tickets, embeddings, WIP tasks, notes tables
- **OpenAI API** — triage classifier, WIP field generation, reply summarisation
- **Voyage AI API** — text embeddings for dedup vector search

---

## Setup

1. Import the workflow JSON into n8n via **Workflows → Import from file**.
2. Attach the credentials above to each node that requires them.
3. In the **Config** node, set `helpdeskSheetId` to your Google Sheets document ID.
4. Ensure the Supabase project has the required tables and the `trg_sync_latest_note` DB trigger (see `infor/` SQL migration files — not committed).
5. Activate the workflow.

---

## Exporting / updating the workflow JSON

1. In n8n, open the workflow → **⋮ menu → Download**.
2. Replace the JSON file in this repo with the downloaded file.
3. Commit with message format: `chore(n8n): export <workflow name> <short summary>`.
